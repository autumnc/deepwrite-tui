# Deepwrite Open-Source Release Design

**Date:** 2026-03-24
**Status:** Approved

## Overview

Deepwrite is a terminal-based Markdown writing tool. This spec defines the plan to open-source the project so that users can install it with a single command (e.g., `brew install deepwrite`).

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| License | MIT | Matches forked edtui; simple; user-friendly |
| Distribution channels | Homebrew tap + `cargo install --git` + GitHub Releases (pre-built binary) | Covers vibe coders (Homebrew), developers (cargo), and everyone else (binary download) |
| Versioning | SemVer 0.x (start at 0.1.0) | Natural continuation; no premature stability commitment |
| Forked edtui | `publish = false`, independent versioning | Internal implementation detail; users never see it |
| GitHub repo | `tomdhyang/deepwrite-tui` (personal account) | Keep it simple |
| Release automation | cargo-release + git-cliff + cargo-dist | One local command triggers the full pipeline |

## Phase 1: Pre-Release Cleanup

### 1.1 Remove tracked OS artifacts and stale files

- `git rm --cached .DS_Store docs/.DS_Store src/.DS_Store`
- Add to `.gitignore`: `.DS_Store`, `.env`, `*.swp`, `.idea/`, `.vscode/`
- Delete stale `crates/edtui/.github/` directory (leftover upstream CI workflows, not used by this repo)

### 1.2 Add required files

| File | Purpose |
|------|---------|
| `LICENSE` | MIT license, copyright Tom D.H. Yang. Preserve `crates/edtui/LICENSE.md` with original author's (Philipp Reiter) copyright |
| `README.md` | Project intro, screenshots, installation instructions, usage, config |
| `CONTRIBUTING.md` | Fork-branch-PR workflow, conventional commits, dev setup |
| `CHANGELOG.md` | Auto-generated by git-cliff |

### 1.3 Update Cargo.toml metadata (root)

```toml
[package]
name = "deepwrite"
version = "0.1.0"
edition = "2021"
license = "MIT"
description = "A terminal Markdown writing tool with Focus Mode"
repository = "https://github.com/tomdhyang/deepwrite-tui"
homepage = "https://github.com/tomdhyang/deepwrite-tui"
readme = "README.md"
keywords = ["markdown", "tui", "editor", "writing", "focus"]
categories = ["command-line-utilities", "text-editors"]
```

Note: `name`, `version`, `edition`, `description` already exist. New fields to add: `license`, `repository`, `homepage`, `readme`, `keywords`, `categories`. MSRV (`rust-version`) is omitted for now since we don't test it in CI.

### 1.4 Mark forked edtui as non-publishable

Add to `crates/edtui/Cargo.toml`:

```toml
publish = false
```

## Phase 2: CI/CD Setup

### 2.1 CI Workflow (`.github/workflows/ci.yml`)

Triggers: push to main, PRs

Jobs:
- `cargo fmt --check`
- `cargo clippy -- -D warnings`
- `cargo test`
- Matrix: ubuntu-latest, macos-latest, windows-latest

### 2.2 Release Workflow (auto-generated by cargo-dist)

Triggers: git tag push (e.g., `v0.1.0`)

Build targets:
- `x86_64-apple-darwin` (macOS Intel)
- `aarch64-apple-darwin` (macOS Apple Silicon)
- `x86_64-unknown-linux-gnu` (Linux x64)
- `x86_64-pc-windows-msvc` (Windows x64)

Outputs:
- GitHub Release with pre-built binaries
- Shell installer script (`installer.sh`)
- PowerShell installer script (`installer.ps1`)
- Updated Homebrew formula

### 2.3 Local Release via cargo-release (`release.toml`)

> **Note:** Originally planned for release-plz, but switched to cargo-release due to a known release-plz bug with workspace path dependencies ([#2595](https://github.com/release-plz/release-plz/issues/2595)).

Run locally: `cargo release patch --execute` (or `minor`)

Behavior:
- Bumps version in `Cargo.toml`
- Runs `git-cliff` pre-release hook to update `CHANGELOG.md`
- Commits with `chore(release): release <version>` (skipped by git-cliff)
- Creates git tag (e.g., `v0.1.1`)
- Pushes commit + tag to origin
- cargo-dist detects the tag and builds/publishes automatically

Configuration (`release.toml`):
```toml
allow-branch = ["main"]
sign-commit = false
sign-tag = false
publish = false
pre-release-hook = ["git-cliff", "-o", "CHANGELOG.md", "--tag", "{{version}}"]
pre-release-commit-message = "chore(release): release {{version}}"
```

### 2.4 Homebrew Tap

Create repo `tomdhyang/homebrew-tap` on GitHub. cargo-dist auto-updates the formula on each release.

Note: `brew tap tomdhyang/tap` maps to GitHub repo `tomdhyang/homebrew-tap` (Homebrew convention).

cargo-dist config in `Cargo.toml`:
```toml
[workspace.metadata.dist]
installers = ["shell", "powershell", "homebrew"]
tap = "tomdhyang/homebrew-tap"
publish-prereleases = false
```

User installs via:
```bash
brew tap tomdhyang/tap
brew install deepwrite
```

## Phase 3: Versioning Strategy

### Version format

SemVer `0.MINOR.PATCH` until 1.0.

| Change type | Version bump | Example |
|-------------|-------------|---------|
| New feature | Minor | 0.1.0 -> 0.2.0 |
| Bug fix | Patch | 0.2.0 -> 0.2.1 |
| Breaking change | Minor (in 0.x) | 0.2.1 -> 0.3.0 |
| Stable release | Major | 0.x.y -> 1.0.0 |

### Commit convention

Conventional Commits (already in use):
- `feat:` -> Features section in CHANGELOG, triggers minor bump
- `fix:` -> Bug Fixes section, triggers patch bump
- `feat!:` or `fix!:` -> Breaking change, triggers minor bump (in 0.x)
- `docs:`, `chore:`, `ci:` -> No version bump

### Automation

`cargo release` bumps the version, updates the changelog via git-cliff, commits, tags, and pushes — all in one command. cargo-dist then handles binary building and distribution automatically.

### edtui versioning

Independent from deepwrite. Not published to crates.io. Version only meaningful internally.

### Graduation to 1.0

Criteria:
- config.toml format is stable
- Core features (Browse + Edit + Focus Mode) are stable
- Active user base with converging feedback

## Phase 4: Release Workflow (Day-to-Day)

```
Write code with conventional commit messages
        |
        v
Push to main
        |
        v
CI runs (fmt, clippy, test)
        |
        v
Ready to release? Run locally:
  cargo release patch --execute  (or minor)
        |
        v
cargo-release automatically:
  - Bumps version in Cargo.toml
  - Runs git-cliff to update CHANGELOG.md
  - Commits + creates git tag (e.g., v0.2.0)
  - Pushes to origin
        |
        v
cargo-dist triggers:
  - Build 5 platform binaries
  - Create GitHub Release
  - Generate install scripts
  - Update Homebrew tap formula
```

## Tool Stack Summary

| Concern | Tool |
|---------|------|
| Changelog generation | git-cliff |
| Release automation | cargo-release (local) |
| Binary building & distribution | cargo-dist |
| Homebrew | cargo-dist (auto-generates formula) |
| CI (PRs/pushes) | Custom ci.yml (fmt + clippy + test) |
| CI (releases) | cargo-dist generated release.yml |

## Implementation Order

1. Pre-release cleanup — .gitignore, remove tracked artifacts, LICENSE, Cargo.toml metadata, delete stale edtui workflows
2. Set up CI workflow (fmt + clippy + test on push/PR) — quality gates first
3. Write README.md, CONTRIBUTING.md — these should exist before release automation creates visible PRs
4. Initialize cargo-dist (`dist init`) — targets: macOS Intel/ARM + Linux x64 + Windows x64; installers: shell + powershell + homebrew
5. Set up git-cliff (`cliff.toml`)
6. Create Homebrew tap repo (`tomdhyang/homebrew-tap`)
7. Set up cargo-release (`release.toml`) with git-cliff pre-release hook
8. First release: tag `v0.1.0`
